## 失败模式 / 待改进

1. **31 个 0 端点网络**：大号文字字符、箭头三角、符号轮廓形成的闭环。
   当前仅靠尺寸（≥50px）过滤，残留较多。改进方向：OCR 文字块掩膜先行剔除。
2. **空心圆环不合并**：本图用空心圆环做接线点，追踪器只处理实心圆点。
   对导线级 From-To 可接受（导线保持独立），但母线归属需后处理规则。
3. **线宽 1.9px 太细**：8px/单位下骨架偶有断裂；提分辨率到 12px/单位更稳，
   代价是 2.25 倍像素量与时间。
4. **1 端点网络（7个）**：多为导线伸出试点边界所致，全图分块时需跨块拼接。
5. **OCR 缺失**：见下。

## OCR 状态（降级，如实记录）

- PaddleOCR：`pip install` 因系统包冲突失败（typing_extensions 等 debian 包无法卸载，
  `--no-deps` 强装后缺 paddlex 等依赖链，补不完）。
- Tesseract：二进制曾存在（chi_sim+eng），被虚拟机重置删除；`apt` 被后台进程锁住
  且源列表中无 tesseract-ocr 包，装不回。
- **降级方案**：`ocr.py` 实现文字块检测（形态学闭运算+连通域，pilot2 检出 12 块），
  识别引擎缺失，仅检测不识别；`tracer.py` 无引擎时自动降级，From-To 中无文字的记"未标注"。
- 文字绑定逻辑（按距离绑最近导线）已写好，待引擎可用即插即用。

## 全图放大可行性评估

| 项 | 评估 |
|----|------|
| 渲染 | 预过滤后约 1 分钟/400×400单位区；全图 13867×14018 需分块 |
| 追踪 | 3200² 图约 45 秒；随像素量线性增长 |
| 分块策略 | 以 2000×2000 单位/块、200 单位重叠计约 49 块，预计数小时 |
| 跨块拼接 | 未实现；需在重叠带匹配端点，是主要工程工作量 |
| 内存 | 9600²（92M像素）实测可行；单块不建议超过 16000² |
| 总体 | **可行，但需 1-2 天工程量**：分块管线 + 跨块拼接 + OCR 引擎 + 文字掩膜 |

## 主要局限（汇总）

1. OCR 识别引擎不可用（仅检测）——环境限制，非算法问题
2. 空心圆环连接语义未处理（本图惯例）
3. 文字/符号闭环网络需 OCR 掩膜配合过滤
4. 未实现分块跨页拼接，全图追踪需后续工程
5. 虚拟机重置会清空 `/usr/local` 的 pip 包，已迁移到 `~/workspace/.pylibs`
