# 视觉追踪项目纪律要求

> **每次为本项目写代码 / 执行代码前，先读一遍本文件，逐条对照。**

## 1. 目标（一句话）

**一套纯视觉管线，输入格式无关**：DXF、PDF、图片——统一渲染成像素，走同一套流程：

渲染 → 二值化 → 细化 → 导线追踪 → 器件框识别 → OCR 认字 → From-To 表

## 2. 铁律：不许解析矢量图元做追踪

- 只看像素。DXF 里的 LINE / TEXT / ARC / CIRCLE / LWPOLYLINE 等图元**不许**用于追踪逻辑。
- 合法预处理只有：渲染成图、按框裁切、图层开关（如关闭背景图层）。
- PDF → 渲染器转像素；图片 → 直接进像素流程。三种输入共用同一套下游。

## 3. 方法：分框 → 单框试点 → 批量复制

1. 大图先找分图框：白色内区域连通域检测 → 长宽比过滤（1.44~1.46）→ 网格完整性补漏。
2. 框内再找器件框（小矩形 = 用电器）；标题栏格子必须过滤（底部位置条带 + 导线是否接入边）。
3. 单框完整跑通、人工看叠加图确认后，再批量复制到其余框。**不许没验证就批量**。

## 4. From-To 表格式（用户确认版）

列：序号 | 起始用电器 | 起始管脚 | 管脚功能 | 目标用电器 | 目标管脚 | 管脚功能 | 导线线号 | 备注

- **一行 = 线号在图面上的一次出现**：图面上线号出现几处就计几行（2026-10-18 用户明确：有的线号名称是重复的，框#112 的 36 行 = 图面上 36 处出现）。同一线号标在不同物理导线上，各计一行
- 管脚号 = 端子圆环旁编号（如 BD176-21）
- 管脚功能 = 器件框内文字（如 FL Speed Sensor Power）
- 导线线号 = 导线上的编号（如 IPB021_01 BR/G 0.35）
- **边界端口也要成行**：导线出框/远端未知时，目标用电器记"—（出框）"，线号认不出记"未识别"，不许丢行（2026-10-18 框#52 教训：视觉版 14 行 vs 真值 23 行，差的 9 行就是 3 条漏标签 + 6 个边界端口）
- **跨图跳转符号的目标必须进 TO 列**（2026-10-18 用户明确）：导线末端的三角箭头是超链接跳转指示符号，其旁文字（如 XF11 IBS POWER）是跳转目标——目标用电器记该文字（如 XF11 IBS POWER），目标管脚记"—"，备注加"跨图跳转"。不许只记"—（出框）"把目标丢了
- **INLINE 连接器按连接器建模，不按拼接点**（2026-10-18 用户明确）：INLINE 是线束与线束对接的连接器，有两端代号（如 FLH 端 INLINE-FLH-IPH-L-J1、IPH 端 INLINE-IPH-FLH-L-J1），数字（如 20）是管脚号。目标用电器记"INLINE连接器"，目标管脚记管脚号（如 20），备注写清两端代号。禁止把两端代号拼成一串塞进管脚列、把管脚号丢进功能列
- **拼接点表示规范**（2026-10-18 用户明确）：拼接点代号统一用完整形式（如 INLINE-IPH-FLH-L-J1、INLINE-FLH-RRDH 35），去重、不拼接、不截断；管脚功能列对拼接点一律记"—"。行模型：器件管脚→拼接点（起始=器件/管脚/功能，目标=拼接点/代号/—）；拼接点→跳转目标（起始=拼接点/代号/—，目标=跳转文字/—/—，备注"跨图跳转"）；跳转入口→拼接点保持。注意图面一个拼接点常印两个并排标签（如 INLINE-RRDH-FLH 与 INLINE-FLH-RRDH 35），取含编号的完整形式

## 5. 已发现的画法约定

- 导线终止于**端子圆环**，不直接进器件框；圆环到器件框有间隙，旁有引脚标注。
- 关联只认经端子圆环的；"导线贴近器件框边即关联"已废弃（曾产生 54 个误关联）。
- 接线点有实心圆点与空心圆环两种，都要处理。

## 6. Windows 交付约束（硬）

- 最终代码跑在 **Windows** 上交付给客户；Linux 只做开发验证。
- 只允许有 Windows wheel 的 pip 包（rapidocr_onnxruntime / onnxruntime / opencv-python / numpy / Pillow / matplotlib / ezdxf 等）。
- **禁止**依赖 apt 系统包、系统级二进制。
- 路径一律 pathlib / os.path；不写 shell 特有调用。
- 交付附 requirements.txt（pin 版本号）+ Windows 安装运行说明（装 Python → pip install -r requirements.txt → 运行）。

### 6.1 Windows 实测 checklist（2026-10-18 血泪教训：Linux 跑通 ≠ Windows 能跑）

每次改代码对照查：
- [ ] **中文路径**：`cv2.imread` 不支持中文路径，改用 `PIL.Image.open` + `np.array` + `convert('L')`
     （注意 PIL 是 RGB，`cv2.cvtColor(BGR2GRAY)` 会通道反转；灰度图直接 `convert('L')`）
- [ ] **OpenCV 版本**：4.14 不支持 bool 数组（`cv2.rectangle` 报错）；用 uint8（255/0）代替 bool（True/False），
      注意 `~inner` 语义变化（bool 逻辑非 vs uint8 按位取反），改写时用"先画外圈 255 再挖内圈 0"
- [ ] **numpy 2.x 兼容**：opencv-python 与 numpy 大版本搭配检查（4.8 配 numpy 1.x，4.10+ 配 numpy 2.x）
- [ ] **ezdxf 跨平台渲染**：不同平台/版本渲染结果可能有差异（字体 fallback），render.png 要对 hash 或并排比
- [ ] **换行符/编码**：文本文件读写指定 `encoding='utf-8'`，Windows 默认 GBK 会炸中文

## 7. 诚实纪律

- OCR 认不出记"未识别"；无文字依据的关联记"待确认"。**不编造**。
- 机器跑的结果 vs 人工手读的，必须区分标注，不混为一谈。
- 已知局限如实写进报告，不藏不吹。

## 8. 执行纪律

- 文件没到齐不开工。
- 大动作前先讲思路；先给示例确认格式，再批量。
- 交付前自己先跑通验证；汇报带日期时间。
